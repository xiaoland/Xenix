# 审计中心 UI/UX 设计

本文件细化 [产品与技术方案](design.md) 的交互；[可交互草图](prototype.html) 只使用合成数据，是设计评审材料，不是生产 UI、Qt 实现或 UI Lab 验收证据。
草图实现范围包括审计分栏、解释/来源/参数切换、会话范围、搜索、缺失/失败状态和跨中心定位；任务中心在草图中复用左侧选择器展示详情，生产任务中心采用下方线框的上列表/下详情结构。浏览器工具拒绝本地文件 URL，本轮未完成草图浏览器验证。

## 用户路径与信息层次

首要路径是“选一个产出 → 看懂 Agent 的解释 → 根据具体疑问查看证据 → 返回解释”，不是先阅读技术参数或自由探索一张复杂关系图。
详情默认页命名为“解释与证据”，将目的、方法选择、结果解读、局限与相应证据入口放在一起；其他页为“输入与来源”和“参数与记录”，避免把支持结论的证据藏在第四个标签页。
不要求 Agent 按固定模板填四段空话；显示层区分执行前说明与执行后解读，并为类型化事实提供清晰标签，Agent 的自然段按原意呈现。

| 位置 | 内容与动作 | 用户收益 |
| --- | --- | --- |
| 窗口顶栏 | 标题、当前会话/所有会话、当前会话名称。 | 知道正在查看哪一批工作，不将全局任务误认为当前工作。 |
| 左栏 | 类型、搜索、产出名称/类型/时间，必要时显示生成/引用和说明状态。 | 先选自己认得的产物，而非内部任务 ID。 |
| 详情标题 | 名称、类型、时间，单独显示关联任务状态和说明状态。 | “任务成功”和“Agent 已解释”不会被混成一个成功徽标。 |
| 默认页 | 执行前说明、结果解读、限制、关联证据摘要。 | 不懂模型参数也能理解选择和结果。 |
| 输入与来源 | 当前对象的有序上游列表/树、输入角色/别名、逐级展开。 | 知道用了哪些数据，不需要读完整全局 DAG。 |
| 参数与记录 | 提交/实际/调参选中三个分组或对照表，完整原始记录折叠。 | 避免横向宽表和 JSON 抢占主要阅读空间。 |
| 固定动作区 | 打开产物、查看任务、来源会话。 | 用户无需滚到底才能执行主要动作。 |

生产窗口建议默认 1100×740 逻辑像素，在可用工作区内收缩；主分隔器左栏约 300，右栏至少约 480，允许用户拖动但不允许完全折叠列表；800×600 为紧凑验证尺寸，尺寸是初始设计值而非像素对齐断言。
在紧凑窗口中筛选器换为两行、参数采用垂直分组，解释自然换行；详情只有一条主纵向滚动，原始 JSON 可以单独横向滚动，主要动作保持可达。
使用项目现有 Qt Widgets、Fusion/平台样式和共享字体，新增局部样式不改变整个应用主题；HTML 草图的颜色和尺寸只表达层次，最终以 Qt UI Lab 捕获为准。

## 选择、刷新与导航

默认在有结果的清单中选中第一项，避免右侧大块空白；刷新按稳定对象键保留选择和滚动位置，不自动跳到最新项，不覆盖用户展开的原始记录。
列表筛选导致原选择不可见时选择首个匹配项并更新详情；无匹配项清空详情及旧动作，不留下上一个对象的可点击按钮。
返回上游前保存筛选、列表选择、详情页和滚动位置；上游对象通过详情导航显示，不偷偷扩充当前会话清单；返回恢复原上下文。
从任务打开产出：一个主产出直接定位，多个主产出显示“该任务的产出”筛选并允许清除；无产出按钮禁用并说明原因，不能打开一个看似无故空白的中心。
从审计打开任务同样按稳定 domain/reference 定位；跨中心导航只调整目标中心必要筛选，展示定位提示并允许返回原筛选，不改变主窗口会话。
只有明确点击“来源会话”才切换主窗口会话；当前会话模式随后跟随主窗口变化，所有会话模式保持不变；来源已删除时保留记录并禁用该动作。
列表查询与详情查询分别使用请求代次；快速切会话/筛选/对象、关闭窗口、重新打开均不能让旧返回覆盖新视图；细节加载失败不把列表伪装成失败或空结果。
可见时只刷新会变化的任务/说明状态，静态长文本不闪烁；错误暂停自动重试，提供明确重试；隐藏/关闭停止窗口轮询，关闭清理完成后才能释放应用服务。

## 状态与文案

| 场景 | 主要文案/呈现 | 可用动作 |
| --- | --- | --- |
| 无当前会话 | “打开一个会话查看相关产出，或切换到所有会话。” | 切换所有会话。 |
| 当前会话无产出 | “此会话尚无可审计的产出。” | 仍可使用范围和搜索，不显示虚假零指标。 |
| 筛选无匹配 | “没有符合筛选条件的产出。” | 清除筛选。 |
| 正在读取 | 列表/详情分别显示读取状态，禁止旧对象动作。 | 允许修改筛选或切换对象。 |
| 任务未完成 | 展示执行前说明，“等待任务结果，尚无结果解读。” | 查看任务；取消在任务中心。 |
| 产出已完成但未解读 | “结果已生成，Agent 尚未解读。” | 查看现有证据和产物；不会自动调用 LLM。 |
| 历史说明缺失 | “此产出未保存 Agent 解释。” | 查看已有来源和记录。 |
| 部分失败 | 保留已有产出，同时展示相关任务失败/取消。 | 查看错误和日志。 |
| 文件缺失 | “记录仍可查看，但产物文件不可用。” | 打开动作禁用，其余证据正常。 |
| 来源不可用 | “来源会话已不可用。”或“来源未记录”。 | 区分已知但删除与从未记录。 |
| 读取失败 | “读取失败，请重试。”附可展开诊断。 | 重试；不以“暂无产出”掩盖。 |

状态同时使用文字与图形，不只用红绿区别；“已有解读”用中性样式，不暗示系统已验证 Agent 正确。
说明旁使用短标签“Agent 提供”；展开帮助解释“以下解读由 Agent 提供，可查看对应执行记录”，不在每个段落重复警告干扰阅读。
重要局限紧邻结论而非折叠到底部；技术参数、路径和完整 JSON 不作为默认正文；没有自然语言解释时也不把 JSON 自动包装成解释。

## 可访问性与语言

键盘顺序为范围 → 类型/搜索 → 列表 → 标签页 → 详情中的证据 → 主要动作，列表支持上下键，Enter 打开所选主产物，空态不触发打开；关闭快捷键只关闭窗口，不取消任务。
使用可见焦点、明确 accessibleName 和稳定 semantic identity，例如 audit.scope、audit.output.list、audit.explanation、audit.open-artifact、jobs.scope、jobs.cancel；重复项使用真实对象键的 item reference，测试不能依赖中文文案定位对象。
中文和英文 UI 采用同一状态和布局逻辑；语言切换不重置会话范围、对象选择或页签，已持久化 Agent 说明保留原会话语言，不因界面语言切换隐式重译或收费。
验证长中文解释、长英文名称、长参数值和不同缩放；工具提示可以补充截断标题，但不作为读取关键证据的唯一方式。

## GammaRay 排查路径

GammaRay 仅作为开发诊断工具，先在相同状态的 Qt UI Lab 场景复现，再检查对象树、布局边距/stretch、sizeHint/最小尺寸、可见性、焦点顺序、信号连接和存活的 timer/worker，修复后回到同一场景捕获并重跑行为测试。
本轮 PATH 查询没有找到 gammaray 命令，仅能说明当前命令不可用，不能据此断言机器未安装；不会为本轮设计擅自安装软件或注入用户正在运行的实例。
启用前核实本机 GammaRay probe 与实际 PySide/Qt/体系结构的兼容性，再用隔离的 UI Lab 或 XENIX_APP_HOME 实例；本轮 UI Lab 捕获报告 PySide/Qt 6.11.1，该值只是环境证据，不是永久依赖约束。
GammaRay 不是验收依赖；不可用时使用既有 tree.json、manifest.json、Qt 日志和 native smoke 定位，不能因诊断器缺失跳过 UI 验证。
