# 审计中心与任务中心整合

- **目标**：将数据集 lineage/audit 扩展为统一审计中心，覆盖模型、训练及调参配置、图表、报告和应用结果；任务中心增加当前会话/所有会话选择器，承接执行详情后删除训练消息专属详情功能。
- **授权边界**：用户已明确授权整理提交现有材料并开始实现；先提交本任务设计基线，再依次实施；2026-09-20 用户手动验收通过后，进一步授权收尾、提交、推送、创建 PR 和合并。浏览器必须通过 Browser Use 使用系统 Helium，不使用内置浏览器。
- **当前事实**：审计中心、两阶段 Agent 解释、产出来源及新迁移已经实现；两个中心具备当前/全部会话范围和相互定位；旧训练详情窗口及按钮/工厂/信号/动作已经删除。
- **方案**：采用“审计中心 / Audit Center”命名，详情优先展示 Agent 对目的、选择依据、结果含义和局限的通俗解释，再连接来源、实际配置与证据；执行前说明必填，结果后解读独立持久化，明确显示尚未解读或历史缺失。任务中心负责执行、日志与取消；复用领域权威与稳定身份。
- **验收出口**：[验收方案](acceptance.md) 定义 A1–A10，覆盖真实领域来源、两阶段解释、会话隔离、UI 行为和删除替代能力；新增 11 类生产 UI Lab 场景，结合自动合同测试、截图人工检查和原生窗口验证。
- **预演结果**：已核查 12 项边界并调整实施落点，包括预处理子进程、自动评估、应用输入、旧 Thread 工具发现、XTT/分页、跨会话解释和旧链路删除；未发现必须并行的依赖。现有相关基线 23 项测试通过，现有 UI Lab 场景捕获成功；设计基线已提交为 `749ce92`，实现和验证结果见[验收记录](results.md)。
- **实施状态**：[线性计划](plan.md) 的 01–10 已完成；实现与人工验收已完成，进入提交和 PR 合并交付阶段，未发布二进制。最终 verify 的 318 项测试、补充闭环测试、原生 Qt 检查、打包及打包烟雾检查均有记录。

本任务采用一个顺序实施计划，不建立并行 tracks 或额外任务图；[产品与技术方案](design.md) 拥有范围和契约，[UI/UX 设计](ui-design.md) 拥有交互，[验收方案](acceptance.md) 拥有通过条件，[计划与预演](plan.md) 拥有实施步骤及本轮证据，避免重复维护多个计划。

[HTML 草图](prototype.html) 是设计阶段参考；实现阶段直接检查生产 Qt 窗口及 UI Lab。Browser Use 当前只列出内置浏览器，未暴露 Helium，因此遵从用户要求没有使用内置浏览器。GammaRay 命令不可用，使用 Qt 的结构捕获与原生窗口验证。
