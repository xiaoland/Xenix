# 审计中心与任务中心整合

- **目标**：将数据集 lineage/audit 扩展为统一审计中心，覆盖模型、训练及调参配置、图表、报告和应用结果；任务中心增加当前会话/所有会话选择器，承接执行详情后删除训练消息专属详情功能。
- **授权边界**：用户已明确授权整理提交现有材料并开始实现；先提交本任务设计基线，再依次实施。浏览器必须通过 Browser Use 使用系统 Helium，不使用内置浏览器。
- **当前事实**：数据集已有持久化谱系；模型有参数和评估证据但缺少直接会话来源；图表保存摘要而非完整配置；旧训练详情还承担日志和文件打开，现有 Jobs 不能完全替代。
- **方案**：采用“审计中心 / Audit Center”命名，详情优先展示 Agent 对目的、选择依据、结果含义和局限的通俗解释，再连接来源、实际配置与证据；执行前说明必填，结果后解读独立持久化，明确显示尚未解读或历史缺失。任务中心负责执行、日志与取消；复用领域权威与稳定身份。
- **验收出口**：[验收方案](acceptance.md) 定义 A1–A10，覆盖真实领域来源、两阶段解释、会话隔离、UI 行为和删除替代能力；新增 11 类生产 UI Lab 场景，结合自动合同测试、截图人工检查和原生窗口验证。
- **预演结果**：已核查 12 项边界并调整实施落点，包括预处理子进程、自动评估、应用输入、旧 Thread 工具发现、XTT/分页、跨会话解释和旧链路删除；未发现必须并行的依赖。现有相关基线 23 项测试通过，现有 UI Lab 场景捕获成功；新功能尚未实现或验收。
- **下一步**：实施从 [线性计划](plan.md) 的 01“固定合同”开始，依次推进至 10“收口”，不提前删除旧能力。当前无必须由用户补充的决策。

本任务采用一个顺序实施计划，不建立并行 tracks 或额外任务图；[产品与技术方案](design.md) 拥有范围和契约，[UI/UX 设计](ui-design.md) 拥有交互，[验收方案](acceptance.md) 拥有通过条件，[计划与预演](plan.md) 拥有实施步骤及本轮证据，避免重复维护多个计划。

[HTML 草图](prototype.html) 提供合成状态示例；浏览器安全策略阻止本轮打开本地 URL，因此尚未做浏览器交互/视觉验证。GammaRay 的当前命令不可用，设计已给出兼容核实和 UI Lab 排查路径，非实施阻塞。
