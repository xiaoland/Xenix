# 审计中心设计提案

状态：基础方案已获用户认可；2026-09-20 补充用户强调的 Agent 通俗解释要求，以下方案均未实现。

本轮补充的 [UI/UX 设计](ui-design.md)、[验收方案](acceptance.md)、[线性实现计划与预演](plan.md) 分别拥有详细交互、通过条件和实施顺序；本文继续拥有产品范围与技术决策。

## 目标和范围

用户需要回答：这个产出使用什么输入、经过什么操作、实际用了哪些配置、有什么证据支持结果，以及有哪些限制。
目标用户没有专业审计能力，因此 Agent 必须提供面向业务用户的解释，帮助其理解和判断，而不是要求用户自行读懂参数、谱系或指标。
推荐界面命名为“审计中心 / Audit Center”；信任来自可检查的证据，不设置缺乏依据的可信分数或“已验证正确”标记。

| 入口 | 用户问题 | 职责 |
| --- | --- | --- |
| 会话 | Agent 做了什么，结果意味着什么？ | 业务解释、普通工具展开、数据集派生摘要和产物链接。 |
| 任务中心 | 工作进行到哪，为什么失败，如何停止？ | 后台任务筛选、状态、起止时间、错误、日志、取消和产出导航。 |
| 审计中心 | 结果从哪里来，配置是什么，证据是否充分？ | 输入链、执行配置、评估和限制、产物打开及来源导航。 |

本轮覆盖已注册的数据集、训练模型、图表、评估/分析报告、模型应用结果及其他用户产物；训练参数属于模型详情，不单独成为产物条目。
数据集导出文件和模型二进制归到对应业务对象下面，避免重复条目；报告既能从模型详情访问，也可按报告类型查找，但只有一个稳定对象身份。
普通查询回答的逐句事实核查、自动复跑、合规认证、防篡改存证不在本轮范围；Knowledge 文档管理继续属于 Knowledge Workspace，不把知识源文件混入 Agent 产出列表。

## 审计中心交互

原主窗口 Datasets 入口替换为“审计中心”，继续使用独立非模态窗口；默认当前会话，增加“当前会话 / 所有会话”选择器，与任务中心保持一致。
没有已保存会话时，当前范围显示说明性空态，可主动切换所有会话；空 thread_id 不得被解释为全局查询。
窗口打开时同步当前会话；可见期间切换会话会更新当前会话范围并废弃过期异步返回；所有会话模式不因主窗口切换会话而重置。
筛选包括类型和名称/身份搜索，筛选后分页、按产出时间倒序；跨中心定位具体对象时调整必要筛选确保目标可见，并显示实际范围。

默认详情页采用“解释与证据”，另设“输入与来源”和“参数与记录”；解释与对应事实并列，不将关键证据藏在独立末级页签。窗口布局、状态文案、键盘、紧凑尺寸及两个中心的线框以 [UI/UX 设计](ui-design.md) 为准。

详情首先展示 Agent 的通俗解释，随后提供对应证据入口、键值表和紧凑来源树，完整 JSON 位于可展开的原始记录区；缺少信息时给出具体原因。
来源树逐级展开上游，保留多输入和别名，支持点击查看及返回；跨会话上游可查看，但不因此计入当前会话清单；不引入自由布局图编辑器。
来源会话按钮打开仍存在的会话；本轮保证会话导航与 ToolCall 身份展示，不在缺少现有定位接口时假称支持精确滚动到消息。

| 产出 | 详情重点 |
| --- | --- |
| 数据集 | 导入文件名/工作表、代数、全部输入/别名、SQL/清洗/变换参数、Agent 解释、导出文件。 |
| 模型 | 数据及角色绑定快照、目标/特征、算法、提交与实际参数、调参网格及选中值、评估与最终模型训练范围、文件和报告。 |
| 图表 | 数据集、字段和图内变换、提交 spec、实际 spec/词云配置、渲染器版本、行数、截断、警告和文件。 |
| 评估/分析报告 | 关联数据/模型/任务、已记录的评估方法、指标、基线、分割与训练范围、局限和报告文件。 |
| 应用结果 | 输入模型与数据集、角色绑定、应用配置、生成列和结果数据集/文件。 |
| 其他产物 | 注册类型、标题、生成时间、可证实的生成来源和输入；未记录类型专属证据时明确说明。 |

## 证据含义

### Agent 解释是交付内容

每个新生成的业务产出必须关联 Agent 解释，不能只在最后一条聊天回复里泛泛说明，也不能把解释作为可有可无的装饰字段；同一操作产生多个文件时可以共用一份解释，但不同模型候选和不同用途的图表必须能找到针对自己的说明。
解释使用当前会话语言，面向不懂机器学习、SQL 或绘图语法的业务用户；优先讲目的、选择的影响和判断边界，涉及专业词汇时就地说明其含义，避免只是把字段名翻译成中文。

| 用户需要理解的问题 | Agent 应说明的内容 |
| --- | --- |
| 为什么要做这一步？ | 与用户业务目标的关系、输入选择及关键假设。 |
| 为什么这样做？ | 方法及重要参数的选择依据和实际影响；只解释影响判断的配置，不逐项复述库默认值。 |
| 得到了什么？ | 结果的业务含义及可核对的证据，区分观察、估计和建议。 |
| 我应该多相信它？ | 数据和评估的局限、可能误导的地方、结论适用条件，以及用户值得检查的事项。 |

例如图表解释需要说明展示什么比较、为何采用该聚合/坐标或筛选，以及是否遗漏或截断数据；模型解释需要说明目标和特征为何合适、关键参数如何影响复杂度/稳定性、评估数字代表什么、是否优于基线，以及哪些业务场景不能直接使用结论。
数据处理解释应说明为何清洗/合并、哪些记录或业务含义受到影响，以及可能损失的信息；模型应用解释应说明模型适用于哪些输入、输出应如何使用，并避免把预测说成已经发生的事实。

### 解释的生成与保存

采用两阶段解释：产出工具调用提交执行前的目的、选择依据和预期影响；拿到真实结果后，Agent 再通过明确的审计说明写入能力补充结果解读、证据引用和限制。执行前不能预写尚未产生的指标或成功结论。
执行前说明随领域来源记录保存；结果解读通过稳定业务对象身份关联，独立于聊天文本持久化，重开会话或删除会话后仍可随保留的产出审查。
结果说明写入接口接收业务对象引用、明确的证据对象引用和面向用户的说明，校验对象及证据存在且属于当前会话可解释范围；系统记录真实作者会话/ToolCall 和写入时间，Agent 不能修改系统证据、来源身份或执行参数。引用校验只证明证据对象有效，不把 Agent 对证据的解释标记为已验证正确。
解释可以由简洁的自由文本表达，不强迫所有产出套用四段固定模板；上述内容是交付质量要求，服务校验非空和关联有效性，Agent 指导与验收检查解释是否具体、有依据且适合非专业用户。
工具 schema 和说明要求新产出携带非空的执行前解释，Agent 交付指导要求取得结果后保存解读；不能仅依靠系统提示的一句“请解释”而没有持久化通路。
后台任务尚未完成时显示已保存的目的与方法说明，结果解读显示“等待结果”；后台完成后若 Agent 尚未继续会话，显示“结果已生成，Agent 尚未解读”，不启动额外的隐式付费会话，也不阻止产物查看。
用户中断或工具部分失败可能留下未完成解释，界面必须如实区分；历史产出显示“未保存 Agent 解释”，不能拿系统模板或事后猜测冒充当时的说明。
后续解读与执行前说明分开标注，保留关联证据身份和说明时间；修正解读不得无痕覆盖已有说明，应保留之前的版本供核对。
同一个产出可在不同会话中被解读，说明版本保留作者会话和用途上下文；当前范围优先展示本会话解读，没有时显示原始生成说明并标明来自其他会话，所有范围默认展示生成会话的解读并可浏览其他会话说明，禁止跨会话无痕覆盖。

### 解释与证据的边界

区分执行记录、Agent 解释和未记录；记录存在不等于业务结果正确，文件可打开不等于结果已验证。
参数区分 Agent 提交的显式配置、服务验证并展开默认值后的实际执行配置、调参选择结果；缺失层标为未记录，禁止用当前版本默认值补写历史值。
评估必须对应真正的证据对象：holdout/out-of-fold 指标不能表述为全量 refit 模型直接测得的分数；不同数据/方法/范围分开展示，保留不完整验证和领域特有限制。
调参展示已保存的搜索空间、选择准则/指标与结果；未保存完整 trial 历史时明确标示，本轮不为补一张表重构调参引擎。
参数选择理由展示显式保存且标注来源的 Agent 说明；说明是面向用户的决策依据摘要，不从参数反推理由，也不要求披露隐含推理。
失败且无产出的工作在任务中心查看输入、错误与日志；成功登记的部分产出可以审计，但须显示关联任务失败/取消，不能暗示整项成功。

## 服务及持久化

新增只读 AuditQueryService，组合 Dataset、ML、Artifact 领域查询和会话关联查询，返回类型化摘要与按需详情；UI 不读取 ORM、不扫描 ToolResult、不拼接文件路径。
另设职责单一的审计说明写入服务，通过 storage repository 追加 Agent 解读及其版本，供 Agent 工具调用；它只拥有解释记录，不拥有领域执行结果，不能让只读查询服务兼任执行权威。
对象键由类型和现有稳定 ID 组成，任务继续使用 domain/reference；不建立第二套产物注册、模型身份或任务状态。
DatasetDerivation 继续拥有数据谱系，MLTask/TrainedModel 与评估结果拥有模型证据，ArtifactService 拥有注册、可用性和打开；审计只投影，不修改配置或调度任务。

### 来源记录

引入内部类型化执行来源值，包含 origin_thread_id 和 origin_tool_call_message_id，由 Tool 适配器从现有 ToolExecutionContext 传入；不能让 Agent 在公开工具参数中伪造归属。
在创建任务/登记产出时持久化来源，不等待 ToolResult：这样超时、多模型调用中途失败或尚未写回结果也不会丢失已接受工作的归属。
MLTask 增加可空、可查询的来源字段，自动评估等后续任务继承；TrainedModel 和 ML Artifact 通过领域任务关联取得来源，不复制同一权威字段。
DatasetDerivation 保留现有 ToolCall 引用并补充发起会话；附件的会话使用关系仍由规范 DatasetBlock 表达，不强行将源文件注册成 Artifact。
新增 Artifact 生成来源记录，由 ArtifactService 与注册在同一数据库事务内保存，承载图表等无 MLTask 产物的操作、来源、结构化输入引用、提交/实际配置及执行前说明；历史或非 Agent 来源允许说明缺失并如实呈现，配置采用有版本的类型化序列化结构。
已有 ML 和数据集导出关系时复用原关系，不把整个 ML 请求/结果或 DatasetDerivation 复制到 Artifact 来源记录；查询适配器负责统一呈现。
来源身份是历史引用，不允许级联删除产出，也不要求尚未提交的 ToolCall FK 立即存在；沿用 DatasetDerivation 的延迟解析原则，丢失会话/消息时明确显示来源不可用。

### 会话成员语义

当前会话审计包含附件、发起的产出及规范工具输入/结果明确引用的业务对象，区分“本会话生成”和“本会话引用”；共享某个输入数据集不是纳入其全部图表或任务的理由。
只识别已知协议的类型化公开句柄，不解析 Markdown 中任意数字/路径；上游闭包只服务来源树，不扩大清单范围。
任务中心当前会话只包含该会话发起的任务及自动后续任务；另一个会话查询已有任务不会重新归属。
共用只读会话对象引用解析模块，避免审计、Jobs 和 Harness 各自维护提取规则，但不同调用方仍采用不同的成员筛选语义。

### 图表与历史兼容

新图表在渲染边界保留提交 spec 和默认值/字段解析后的实际配置；不复制注入的整份数据行，以 Dataset 身份绑定来源；合法字面量不能被递归删除所有 data 字段的“净化”误删。
词云保存实际字段、top_n、尺寸、颜色、字体相关选择及其他执行选项；保留渲染器版本、截断和警告，不承诺跨环境位级复现。
通过正向迁移支持旧状态和新建数据库；历史关联只依据可证明的领域关系和已知生产工具记录恢复，不靠名称、共享输入或时间接近猜测。
历史 ToolCall 可提供“调用记录中的提交配置”，不能冒充实际执行值；历史模型优先读任务和模型元数据，历史图表展示已有摘要和可恢复的提交配置。
历史 ML 归属只接受已知创建工具的明确返回身份，并沿已保存的后续任务关系扩展；task.query 返回不证明创建者，无法唯一确定时保持未知，在所有会话可见。
删除会话后产物与领域证据维持原生命周期，全部范围可显示来源不可用；会话引用关系消失不能导致生成来源和业务产物被清除。
文件缺失与来源缺失分别呈现，文件打不开仍可读证据；对象局部缺失和整个查询失败分别报告，禁止用空清单静默掩盖失败。

## 任务中心与删除范围

任务中心增加当前会话/所有会话选择器，首次默认当前会话；全部范围增加会话列，包含 Knowledge 全局任务、未归属任务和所有 ML 工作。
Knowledge Workspace 发起的任务标为“全局”，不混入当前会话；无法确定来源的旧 ML 任务标为“未记录”，与全局明确区分。
范围、服务、状态和搜索联合筛选后分页；范围变化重置分页，语言切换保留选择；隐藏/关闭停止 UI 轮询，取消继续由 JobScheduler 管理。
用任务中心内详情区替换现有简短 QMessageBox，展示起止时间、输入摘要、错误和领域服务日志；“查看产出”定位审计中心，失败且无产出有明确空态。

| 旧能力 | 处理 |
| --- | --- |
| 任务状态、起止时间、错误、刷新 | 移至任务中心详情。 |
| 日志 | 复用 TaskLogView 与领域查询，在任务中心按需加载。 |
| 模型/报告/结果文件打开 | 移至审计中心，经 ArtifactService/LinkRouter 使用注册身份。 |
| ToolCallDetailView 和训练专属 Details | 删除窗口、工厂、多窗口追踪、动作生成/分发、信号、专用样式及失效测试/翻译。 |
| 普通工具参数/结果展开、model.task.query/stop | 保留；分别属于会话证据和 Agent 执行能力。 |

不再给训练消息添加等价的专属详情按钮；通过主窗口进入两中心，在中心内部交叉定位。

## 实施与验收入口

按 [线性计划](plan.md) 的 01–10 顺序实施，在两个中心承接原有能力后才删除旧链路；[验收方案](acceptance.md) 的 A1–A10 规定真实领域服务、Agent 工具、UI Lab、原生窗口和人工解释审查的出口。
用户已认可设计、验收和预演，并明确授权整理提交后开始实现；产品行为以实际实现和验收结果逐步更新。
