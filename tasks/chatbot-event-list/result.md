# Chatbot EventList Result

## Objective & Hypothesis

- Objective: move Chatbot from direct MessageList rendering to Harness-owned ChatbotEvent projection, with paired tool-call request/result messages rendered as one compact expandable tool item.
- Hypothesis: an explicit projection boundary lets Agent Harness keep storage and LLM-facing tool semantics while Chatbot UI becomes a renderer of user-visible events.

## Implemented State

- Agent Harness persists tool-call request and result as separate records.
- Agent Harness projects those records into one `ChatbotEventKind.TOOL` event.
- Agent Tool Registry owns each registered tool's presentation metadata: semantic icon key and status summary language.
- Request-only tool calls project to pending tool events.
- Completed, failed, and cancelled tool events receive Harness-owned summary/status language.
- Tool result content blocks now include a `tool_event_summary` block before detail and payload blocks when generated by Harness.
- Provider message projection treats `tool_event_summary` as normal text, so tool result summaries can be LLM-facing.
- Chatbot UI renders:
  - user/assistant text events as existing bubbles
  - tool events as `ToolCallItem` rows with icon, summary, chevron, and expandable detail
- Tool events now occupy the full EventList column width.
- Tool icons and chevrons use QtAwesome icons rather than text glyphs, Qt filled arrows, or custom painter drawing.
- Legacy chat-surface naming has been unified to Chatbot/chatbot, while the selected-thread container remains `ThreadDetailView`.
- Auto-height message text browsers ignore wheel events so message content does not become an internal scroll target.
- Chatbot UI no longer inserts turn dividers.
