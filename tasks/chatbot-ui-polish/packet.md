# Chatbot UI Polish

## Objective & Hypothesis

Improve Chatbot UI behavior:

- diagnose and remove recurring console `invalid svg path` warnings during recent conversations
- replace text-as-icon affordances with real icons/spinner widgets
- allow EventList/MessageList free user scrolling while streaming updates arrive
- add a bottom-center floating scroll-to-bottom icon button

Current hypothesis:

- Scroll jank is caused by unconditional `_scroll_to_latest()` calls on every append/update in `ThreadDetailView`, followed by delayed scrollbar max assignment.
- Text icon replacements are local to `main_window.py` and `chatbot.py`.
- SVG warnings are generated by QtSvg while Chatbot previews Vega SVG artifacts, but the source defect is at the Vega SVG generation/post-processing boundary: `vl_convert` outputs hidden empty `d=""` paths that QtSvg rejects.

## Implementation

- SVG:
  - `src/xenix/services/analysis_graph.py` normalizes only Vega SVG output after `vlc.vega_to_svg(...)`.
  - Normalization removes `<path>` elements with missing or empty/whitespace `d` values before the SVG is size-checked and persisted.
  - Wordcloud SVG output is unchanged.
- Icons:
  - `src/xenix/ui/icons.py` now maps `icon_key="text"` to a text icon and exposes plus, spinner, error, and scroll-to-bottom helpers.
  - `MainWindow` History new-thread button uses `ph.plus` instead of `+` text.
  - `AttachmentChip` pending/failed states use spinner/error pixmaps instead of `...` / `!`.
  - The send button uses a spinner icon with empty text while attachments are pending.
- Scrolling:
  - `ThreadDetailView` tracks whether the user is following the latest item.
  - Append/update calls only scroll to bottom while follow mode is enabled.
  - User scroll away from the bottom cancels pending delayed scroll jobs.
  - A bottom-center `scrollToBottomButton` appears when there is content below; clicking it scrolls to bottom and re-enables follow mode.
- Documentation:
  - `docs/30-unit-tdd/chatbot-ui.md` now documents conditional follow-at-bottom behavior.
  - `docs/20-product-tdd/runtime-boundaries.md` now documents Vega SVG empty-path normalization.

## Current Understanding

- `ThreadDetailView._scroll_to_latest_after_layout()` sets the vertical scrollbar to maximum after 4 event-loop ticks.
- `add_message`, `add_tool_event`, `add_usage_event`, `add_thinking_event`, `apply_message_event`, and `apply_chatbot_event` call `_scroll_to_latest()` when `auto_scroll=True`.
- `render_events()` clears and renders all events, then scrolls to latest. This is acceptable for opening/switching a thread unless product decides otherwise.
- Text-as-icon occurrences found so far:
  - `src/xenix/ui/main_window.py`: `_new_thread_button.setText("+")`
  - `src/xenix/ui/chatbot.py`: `AttachmentChip` pending `"..."` and failed `"!"`
  - `src/xenix/ui/chatbot.py`: send button pending attachment state `"..."`
- Current icon helper only exposes tool, chevron, attach, and remove icons. Additional helpers probably belong in `src/xenix/ui/icons.py`.
- Direct construction of current QtAwesome icons under `QT_QPA_PLATFORM=offscreen` produced non-null pixmaps without warnings.
- Direct rendering of simple generated wordcloud and simple Vega SVG artifacts through `QSvgRenderer` produced non-null pixmaps without warnings.
- Runtime diagnosis on `%LOCALAPPDATA%/Xenix/artifacts/**/*.svg` found `Invalid path data; path truncated.` on Vega artifacts, not wordcloud artifacts.
- The warning correlates with hidden empty path elements generated by `vl-convert-python`, e.g. `<path class="foreground" aria-hidden="true" d="" pointer-events="none" display="none"/>`.
- A temp sanitized copy of `graph-smoke-vega-f20bd944a54c.svg` with only empty-`d` path elements removed rendered through `QSvgRenderer` with zero invalid-path warnings.
- A fresh minimal `AnalysisGraphService.graph_dataset(... spec=bar chart ...)` output produced two empty `d=""` path elements immediately, so the root is the Vega generation/post-processing boundary rather than Chatbot markdown or preview mutation.
- Direct `vl_convert.vega_to_svg(...)` on a minimal Vega bar spec produces `<path class="foreground" aria-hidden="true" d="" display="none"/>`, proving the empty path exists before Xenix post-processing.
- Local dependency is `vl-convert-python` `2.0.0-rc1`, a pre-release newer than the latest stable PyPI page (`1.9.0.post1` as of 2026-07-06 lookup). GitHub release notes for `2.0.0 RC 1` mention Vega/Vega-Lite updates but no empty-path SVG fix.
- `vl-convert` documents that conversion uses Vega-Lite and Vega JavaScript libraries inside an embedded V8 runtime, so the actual SVG element shape is likely produced by Vega's SVG renderer as surfaced through `vl-convert`.
- A temporary install of `vl-convert-python==1.9.0.post1` still produced empty `d=""` path elements for both direct Vega and Vega-Lite minimal bar specs. The installed module reports `__version__ == "1.9.0"` and `get_vega_version() == "6.2.0"`.
- Current `2.0.0-rc1` `vegalite_to_svg(...)` also produces empty `d=""` path elements. Therefore downgrading to stable and switching to Vega-Lite does not by itself remove the QtSvg invalid-path warning.
- Git history explains why this warning became newly visible:
  - `2026-06-19` `8b07b3d` switched `analysis.graph` to the Xenix Vega profile and pinned `vl-convert-python==2.0.0rc1`.
  - `2026-07-02` `4e86ead` moved word clouds out of Vega and into Python `wordcloud`.
  - `2026-07-02` `5194b08` / `436aa7a` made Chatbot SVG artifact previews more explicit and rasterized them through Qt SVG preview logic.
  - Direct tests show `QPixmap(path)` and `QSvgRenderer.render(...)` both report invalid path on the same empty-path Vega artifact, so the warning likely became visible because inline artifact preview became more active or console warning exposure changed, not because the empty paths were introduced only by the recent preview code.
- Follow-up diagnosis on `artifact://ea9a55fd424e424abada28cd9ff17cf2` and `artifact://9c89b48eb91f4f2cb68bcec664b6a755` showed missing visual marks are not caused by SVG normalization:
  - persisted SVG files contain no `d=""` paths after normalization
  - the customer-group bar chart still contains five `mark-rect` paths, but each has zero width, e.g. `M480.769...,5.882...h0v52.941...h0Z`
  - the city-level chart is actually generated as Vega `arc` marks, and each arc path is zero-area, e.g. `M0,-160L0,0Z`
  - direct pre-normalization `vlc.vega_to_svg(...)` output for the same prepared specs already has the same zero-area mark paths
  - the bar spec is missing `x2: {scale: "x", value: 0}` or `width`; the pie spec computes `startAngle` and `endAngle` from the same value instead of using pie-transform-generated angle fields

## Decisions

- Preserve the original Chatbot UI improvement scope. Do not narrow this task to SVG only.
- For SVG warnings:
  - normalize Vega SVG output immediately after `vlc.vega_to_svg(...)` and before `_write_svg_output()`
  - remove only `<path>` elements whose `d` attribute is missing or empty/whitespace
  - do not patch vendored `vl-convert`, do not fork Vega, and do not rely on downgrading to stable or switching to Vega-Lite as the fix
  - do not degrade Chatbot SVG preview to a plain link when the SVG is otherwise renderable
  - leave `wordcloud_spec` output alone unless evidence later shows a wordcloud-specific issue
- For text-as-icon cleanup:
  - replace `main_window.py` History new-thread `"+"` with a plus icon
  - replace `AttachmentChip` pending `"..."` with a loading/spinner or pending icon
  - replace `AttachmentChip` failed `"!"` with an error icon
  - replace send-button pending `"..."` with a spinner/pending visual state
  - add icon helpers in `src/xenix/ui/icons.py`
  - add `icon_key="text"` mapping so `data.tokenize` does not fall back to the generic wrench icon
- For scrolling:
  - EventList should auto-follow only when the user is already at/near the bottom
  - when the user scrolls up, streaming event inserts/updates must preserve user scroll position
  - provide a bottom-center floating scroll-to-bottom icon button when not at bottom
  - clicking the floating button scrolls to bottom and re-enables follow behavior
- Documentation:
  - update `docs/30-unit-tdd/chatbot-ui.md` because the current Streaming Contract says `EventList scrolls to the latest visible item`; the new contract is conditional follow-at-bottom behavior.
  - consider a compact `docs/20-product-tdd/runtime-boundaries.md` note that Vega SVG artifacts are normalized to remove non-renderable empty path elements for Qt preview compatibility.
- Follow-up decision after zero-area mark diagnosis:
  - do not add service validation for zero-area/degenerate rendered marks
  - change `analysis.graph.spec` back from the Xenix Vega profile to Vega-Lite
  - downgrade `vl-convert-python` from `2.0.0rc1` to stable `1.9.0.post1`
  - keep the SVG empty-path normalization unless new evidence shows stable Vega-Lite output no longer needs it; prior diagnosis showed `vl-convert-python==1.9.0.post1` can still output empty `d=""` paths
