# Wordcloud Diagnosis

## Evidence

- Latest real app thread: `521f3970f2d443ffa842549e1ccee24b`, title `生成词云图请求`.
- Problem artifact: `6cbf5df5c89d4383bf45b5d01c0d3456`, generated by tool call `b429a574e1cb424c997bb2bee7b01365`.
- The generated spec did not use Vega `wordcloud` transform.
- The generated text mark used random coordinates:
  - `x`: `random() * 600 + 50`
  - `y`: `random() * 400 + 50`
- The output SVG shows obvious near-overlap, for example:
  - `爱情`: `translate(586.851...,104.007...)`, `font-size="68.725...px"`
  - `幻想`: `translate(585.748...,107.330...)`, `font-size="57.945...px"`
- The Agent later claimed Vega has no built-in wordcloud layout and switched to bar/bubble substitutes. That claim is false for the current renderer path.

## Controlled Check

- A direct in-memory Vega `wordcloud` spec over the same `电影类型清理` dataset rendered Chinese terms with positioned text through `vl-convert-python 2.0.0rc1`.
- With an aggressive `fontSizeRange` such as `[12, 88]`, some terms were not placed and appeared as `translate(0,0)` / `font-size="0px"`.
- With conservative ranges such as `[10, 48]`, all 34 terms rendered without zero-position/zero-size nodes.

## Diagnosis

- Primary cause: LLM-authored Vega spec used random text placement instead of `wordcloud` mark-level transform.
- Secondary risk: even real Vega wordcloud can fail to place all words if the font range is too large for the canvas and word count.
- Chinese support is not the primary issue in this case.
- `vl-convert-python 2.0.0rc1` is capable of rendering Chinese wordcloud layout when the spec uses the correct transform and reasonable sizing.

## Recommended Follow-up

- Strengthen `analysis.graph` tool schema/description around wordcloud-specific Vega shape:
  - Use a `text` mark.
  - Use mark-level `transform: [{"type": "wordcloud", ...}]`.
  - Avoid random `x`/`y` placement for wordclouds.
  - Use conservative `fontSizeRange` for Chinese/many-term clouds, for example `[10, 48]` or `[12, 56]` depending on canvas size.
- Consider service-side validation for likely-bad wordcloud attempts:
  - If title contains `词云` / `word cloud`, and a text mark uses `random()` x/y without a `wordcloud` transform, fail with a repair hint.
  - If a rendered SVG has many `font-size="0px"` text nodes, fail with a hint to reduce `fontSizeRange`, increase canvas size, reduce word count, or pre-filter top terms.
