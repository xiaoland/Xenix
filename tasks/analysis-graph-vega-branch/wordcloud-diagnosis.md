## Controlled Check

- A direct in-memory Vega `wordcloud` spec over the same `电影类型清理` dataset rendered Chinese terms with positioned text through `vl-convert-python 2.0.0rc1`.
- With an aggressive `fontSizeRange` such as `[12, 88]`, some terms were not placed and appeared as `translate(0,0)` / `font-size="0px"`.
- With conservative ranges such as `[10, 48]`, all 34 terms rendered without zero-position/zero-size nodes.

## Diagnosis

- Current primary cause: LLM-authored Vega spec still misses required concrete Vega shape details for wordcloud: grouped mark encode (`encode.enter` / `encode.update`) and bounded `fontSizeRange`.
- The existing post-render validation prevents blank artifact success, but its repair hint is not actionable enough: it does not explicitly say `encode.enter`, and it does not mention `fontSizeRange`.
- For long labels and many rows, the current failure threshold can be layout-sensitive because Vega wordcloud placement has stochastic behavior.
- Previous cause: LLM-authored Vega spec used the `wordcloud` transform with the wrong field-binding shape, so the renderer produced an SVG artifact that was syntactically valid but semantically blank.
- Previous primary cause: LLM-authored Vega spec used random text placement instead of `wordcloud` mark-level transform.
- Secondary risk: even real Vega wordcloud can fail to place all words if the font range is too large for the canvas and word count.
- Chinese support is not the primary issue in this case.
- `vl-convert-python 2.0.0rc1` is capable of rendering Chinese wordcloud layout when the spec uses the correct transform and reasonable sizing.

## Recommended Follow-up

- Strengthen `analysis.graph` tool schema/description around the exact wordcloud Vega shape, not only the existence of the transform:
  - Use a `text` mark.
  - Use mark-level `transform: [{"type": "wordcloud", "text": {"field": "<word>"}, "fontSize": {"field": "datum.<count>"}, ...}]`.
  - Use grouped mark encoding: `encode: {"enter": {"text": {"field": "<word>"}, ...}}`.
  - Use conservative `fontSizeRange` for Chinese/many-term clouds, for example `[10, 48]` or `[12, 56]` depending on canvas size.
- Consider service-side validation for likely-bad wordcloud attempts:
  - If a wordcloud mark has no grouped `encode.enter` / `encode.update`, fail before rendering with a specific repair hint.
  - If a wordcloud transform has `fontSize` but no `fontSizeRange`, fail before rendering with a specific repair hint.
  - If title contains `词云` / `word cloud`, and a text mark uses `random()` x/y without a `wordcloud` transform, fail with a repair hint.
  - If a rendered SVG has many empty text nodes or `font-size="0px"` text nodes for a wordcloud mark, fail with a hint to correct field binding, reduce `fontSizeRange`, increase canvas size, reduce word count, or pre-filter top terms.
