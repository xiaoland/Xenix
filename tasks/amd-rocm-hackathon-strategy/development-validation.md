# Radeon Cloud Development and Product Validation

## Scope Completed

The supplied Radeon Cloud environment was used as a Private SSH Radeon target,
not as a product-hosted backend. Validation covered the exact captured Linux ROCm
cell without retaining its access material.

1. The pinned Granite Chat, BGE-M3 Embedding, and RapidOCR OCR recipes were
   materially acquired, self-tested on ROCm, and retired through exact target
   fences.
2. The actual Xenix AMD composition enrolled a Private target, prepared the
   admitted profile, and published three generation-specific provider
   projections through the capability settings owners.
3. Ordinary capability adapters then performed Chat, Embedding, and OCR setup
   against their operation-scoped bindings. The deployment facade was not used
   on the inference path.
4. Retirement reached durable `removed`; a final target inventory verified that
   no product generation/runtime/receipt/tombstone/provisioning artifact or
   owned process remained.

## Failure-driven Product Corrections

- vLLM provisioning must install the exact manifest-declared wheel filename;
  `vllm.whl` is retained only as cleanup compatibility for an earlier draft
  residue.
- The availability mirror can return a forbidden irrelevant `.DS_Store` object.
  The pinned model snapshot excludes that non-model file while every declared
  artifact still receives size/hash verification.
- Exact target retirement can create a missing control lock only after it has
  proved the target marker and the committed retirement tombstone. It never uses
  that compatibility path for ordinary install/start.
- The AMD-enabled package runtime hook must contain real newline characters;
  packaging proof caught and verified this correction.

## What This Does Not Prove

- Local Linux Radeon behavior on a physically compatible host;
- native Windows ROCm, WSL, a Linux graphical desktop, or GUI remoting;
- a different GPU/driver/ROCm/model compatibility cell;
- an offline claim, public Model API behavior, or a hosted inference path.

completion. The later manual acceptance run must use a fresh target root/baseline
and must not reuse a feasibility cache as one-click evidence.
