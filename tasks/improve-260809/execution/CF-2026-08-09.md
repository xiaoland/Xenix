This corrected an earlier optimization assumption: distinct model keys can share one `model.train` call, but repeated parameterizations of the same key cannot share the current `params_by_model` mapping. Tool schema and Skill guidance now state that boundary exactly.

The last clustering report serialized `semantic.verdict=not_evaluated` even though every deterministic semantic check passed, because the runner incorrectly replaced the semantic channel with a required Judge verdict. The runner now derives semantic verdict only from deterministic case checks; Judge status/verdict remain separate. A dedicated offline regression proves that Judge provider failure cannot overwrite semantic pass.
