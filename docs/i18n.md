# i18n Implementation

## Overview

This document describes the internationalization (i18n) implementation in Xenix using vue-i18n with **remote lazy loading**.

## Architecture

### Remote Lazy Loading

The application uses **remote lazy loading** for locale files, which provides several key benefits:

1. **Not Bundled**: Locale files are not included in the JavaScript bundle
2. **Served Separately**: Translation files are served as static assets from `/public/locales/` or a CDN
3. **Over-the-Air Updates**: Translations can be updated without redeploying the application
4. **Reduced Bundle Size**: Initial JavaScript bundle is smaller as translations are loaded on-demand
5. **CDN Support**: Can be served from a CDN for better global performance

**Implementation:**

- Locale files are stored in `public/locales/` directory (not bundled in JavaScript)
- Files are fetched via HTTP requests from `/locales/{lang}.json`
- Can be configured to load from a CDN via `VITE_LOCALE_BASE_URL` environment variable
- `packages/frontend/src/i18n/index.ts` - Core i18n setup with remote loading
- `packages/frontend/src/main.ts` - Async initialization
- `packages/frontend/src/components/common/LanguageSwitcher.vue` - Language selector

### Configuration

Set the locale base URL in your `.env` file:

```bash
# Default: serves from public directory
VITE_LOCALE_BASE_URL=/locales/

# Production: serve from CDN
VITE_LOCALE_BASE_URL=https://cdn.example.com/locales/
```

### Supported Languages

- **English (en)** - Default language
- **Chinese (zh-CN)** - Secondary language

## How to Use

### In Vue Templates

Use the `$t()` function to translate strings:

```vue
<template>
  <h1>{{ $t('home.title') }}</h1>
  <p>{{ $t('home.subtitle') }}</p>
</template>
```

### In Script Setup

Import and use the `useI18n` composable:

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n';

const { t } = useI18n();

const message = t('projects.createSuccess');
</script>
```

### Adding New Translations

1. Add the key to `packages/frontend/public/locales/en.json`
2. Add the same key to `packages/frontend/public/locales/zh-CN.json`
3. Use the key in your component with `$t('key')` or `t('key')`
4. For production CDN updates, upload the updated JSON files to your CDN

Example:

```json
// en.json
{
  "myFeature": {
    "title": "My Feature",
    "description": "This is my feature"
  }
}

// zh-CN.json
{
  "myFeature": {
    "title": "我的功能",
    "description": "这是我的功能"
  }
}
```

## Development Tools

### Translation Validation

Check for missing or unused translation keys:

```bash
cd packages/frontend
npm run i18n:check
```

This will show:

- Missing translations (keys used in code but not in locale files)
- Unused translations (keys in locale files but not used in code)

### ESLint Integration

The project includes `@intlify/eslint-plugin-vue-i18n` for catching i18n issues during development:

```bash
npm run lint
```

ESLint rules configured:

- `@intlify/vue-i18n/no-unused-keys` - Warns about unused translation keys
- `@intlify/vue-i18n/no-missing-keys` - Warns about missing translation keys
- `@intlify/vue-i18n/no-raw-text` - (Optional) Enforces all text to use i18n

## Implementation Details

### Language Persistence

The selected language is persisted in `localStorage` with the key `xenix-locale`. This ensures the user's language preference is maintained across sessions.

### Fallback Behavior

If a translation key is missing in the selected language, the system automatically falls back to English (the fallback locale).

### Type Safety

The `SupportedLocale` type ensures only valid language codes can be used:

```typescript
export type SupportedLocale = 'en' | 'zh-CN';
```

## Testing

### Verifying Remote Loading

To verify that locale files are loaded from remote source (not bundled):

1. Start the dev server: `npm run dev`
2. Open browser DevTools (F12)
3. Go to the Network tab
4. Navigate to the homepage (http://localhost:5173)
5. Look for a request to `/locales/en.json` (not a bundled chunk)
6. Click the language switcher and select "中文"
7. Observe a new network request to `/locales/zh-CN.json`

The locale files should appear as separate HTTP requests, not as part of the JavaScript bundle.

### Manual Testing Checklist

- [ ] Language switcher appears in header
- [ ] Default language is English on first load
- [ ] Switching to Chinese updates all text
- [ ] Switching back to English works correctly
- [ ] Language preference persists after page reload
- [ ] No console errors or warnings about missing keys
- [ ] Layout and formatting look correct in both languages

### Automated Testing

To add automated tests for i18n:

```typescript
import { mount } from '@vue/test-utils';
import { createI18n } from 'vue-i18n';
import HomeView from '@/views/HomeView.vue';

const i18n = createI18n({
  legacy: false,
  locale: 'en',
  messages: {
    en: { home: { title: 'Xenix' } }
  }
});

test('renders with i18n', () => {
  const wrapper = mount(HomeView, {
    global: {
      plugins: [i18n]
    }
  });
  expect(wrapper.text()).toContain('Xenix');
});
```

## CDN Deployment

### Benefits of CDN-Hosted Translations

1. **Over-the-Air Updates**: Update translations without redeploying the application
2. **Global Performance**: Serve translations from CDN edge locations for faster loading
3. **Independent Versioning**: Update translations independently of application code
4. **A/B Testing**: Test different translations without code changes

### Setting Up CDN

1. **Upload locale files to CDN**:
   ```bash
   # Copy locale files to CDN
   aws s3 cp packages/frontend/public/locales/ s3://your-cdn-bucket/locales/ --recursive
   # or use your CDN provider's CLI
   ```

2. **Update environment variable**:
   ```bash
   VITE_LOCALE_BASE_URL=https://cdn.example.com/locales/
   ```

3. **Rebuild and deploy** (environment variable is compiled into the build):
   ```bash
   npm run build
   ```

### Cache Strategy

Configure your CDN with appropriate cache headers:

```
Cache-Control: public, max-age=3600, s-maxage=86400
```

This allows:
- Browser caching for 1 hour
- CDN caching for 24 hours
- Easy cache invalidation when translations are updated

### Updating Translations

To update translations in production:

1. Update the JSON files in `public/locales/`
2. Upload to CDN (overwrites existing files)
3. Invalidate CDN cache for locale files
4. Users will receive updated translations on next page load or language switch

No application redeployment needed!
